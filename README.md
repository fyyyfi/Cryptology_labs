# Cryptology_labs
## 1) Реалізувати алгоритм обчислення контрольної суми (CRC)  
Програмна реалізація алгоритму CRC базується на імітації поліноміального ділення за модулем 2 («у стовпчик»). Програма складається з таких основних етапів:

*   **Підготовка даних:** До вхідного двійкового повідомлення програмно додається $r$ нулів, де $r$ — це ступінь полінома-генератора (довжина полінома мінус один).
*   **Ділення (XOR):** Реалізовано допоміжну функцію для побітового додавання за модулем 2 (`XOR`). Програма проходить циклом по розширеному повідомленню. Якщо поточний старший біт дорівнює `1`, виконується операція `XOR` із поліномом-генератором. Якщо `0` — відбувається зсув до наступного біта.
*   **Результат:** Цикл завершується, коли пройдено все повідомлення. Залишок від цього «ділення» і є нашою контрольною сумою (CRC), яка виводиться на екран.

## 2) Реалізувати алгоритм RC4
Для реалізації шифру RC4 логіку розділено на три блоки, які повністю відповідають математичній моделі алгоритму:

*   **Алгоритм KSA (Key-Scheduling Algorithm):** Спочатку створюється масив станів (S-box) від 0 до 255. Далі, використовуючи введений користувачем ключ, програма проходить циклом по цьому масиву і перемішує його елементи за визначеною формулою, щоб створити початковий псевдовипадковий стан.
*   **Алгоритм PRGA (Pseudo-Random Generation Algorithm):** На цьому етапі генерується потік ключів (гама) такої ж довжини, як і вхідний текст. Програма продовжує перемішувати елементи масиву станів, витягуючи з нього байти для гами.
*   **Процес шифрування/розшифрування:** Оскільки алгоритм є симетричним, використовується одна і та сама функція. Програма бере байти відкритого тексту (або шифротексту) і побітово додає їх (операція `XOR`) до згенерованого потоку ключів. Для зручності перевірки результатів фінальний зашифрований текст виводиться у шістнадцятковому (`HEX`) форматі.
